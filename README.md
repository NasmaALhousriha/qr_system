# نظام الحضور والغياب الذكي للجامعة

## فكرة المشروع

عملت هذا المشروع لاستبدال ورقة التوقيع التقليدية في المحاضرات بنظام رقمي. كل طالب عنده رمز QR خاص فيه، ويتم تسجيل حضوره عن طريق مسح هذا الرمز خلال وقت المحاضرة فقط.

المشروع عبارة عن REST API مبني بـ Express مع Prisma 7 وقاعدة بيانات PostgreSQL.

## الأدوات المستخدمة

- Node.js مع TypeScript (CommonJS)
- Express 5 لبناء الـ API
- Prisma 7 (مع ملف `prisma.config.ts`) و PostgreSQL
- مكتبة `qrcode` لتوليد صور الـ QR

## هيكلية المشروع

قسّمت الكود حسب المسؤوليات، كل طلب بيمرّ بالترتيب: route ثم controller ثم service.

```
src/
├── app.ts                 # إعداد التطبيق وتشغيل السيرفر
├── lib/prisma.ts          # الاتصال بقاعدة البيانات
├── routes/                # تعريف الروابط (express.Router)
├── controllers/           # استقبال الطلب والتحقق من المدخلات وإرجاع الرد
├── services/              # منطق العمل والتعامل مع قاعدة البيانات
├── middlewares/           # معالج الأخطاء المركزي
└── utils/                 # كلاس AppError
prisma/schema.prisma       # جداول قاعدة البيانات
prisma.config.ts           # إعدادات Prisma
tests/api.test.ts          # الاختبارات
```

- **routes:** بتحدد الرابط وبتوجهه للـ controller المناسب.
- **controllers:** بتقرأ بيانات الطلب وبتتحقق منها، وبعدين بتنادي الـ service.
- **services:** فيها منطق المشروع الفعلي والاستعلامات على قاعدة البيانات.

## قاعدة البيانات

| الجدول | وظيفته |
|---|---|
| `Student` | اسم الطالب وإيميله ورقمه الجامعي و`qrCodeToken` عشوائي وفريد |
| `Lecture` | عنوان المحاضرة ووقت البداية ووقت النهاية |
| `Attendance` | بيربط الطالب بالمحاضرة، مع قيد فريد على `(studentId, lectureId)` |

## طريقة التشغيل

المتطلبات: Node.js بنسخة 20.19 أو أحدث، و PostgreSQL شغّال.

```bash
# 1. تنزيل الحزم
npm install

# 2. إنشاء ملف البيئة وتعديل DATABASE_URL فيه
cp .env.example .env        # على ويندوز: copy .env.example .env

# 3. إنشاء الجداول وتوليد Prisma client
npx prisma migrate dev
npx prisma generate

# 4. تشغيل السيرفر (http://localhost:3000)
npm run dev
```

## روابط الـ API

الأخطاء بترجع بالشكل `{ "message": "..." }` مع كود الحالة المناسب.

| الطريقة | الرابط | الوظيفة |
|---|---|---|
| `POST` | `/api/students` | إنشاء طالب. البيانات: `name` و`email` و`studentId` |
| `GET` | `/api/students` | عرض كل الطلاب |
| `GET` | `/api/students/:id/qr` | إرجاع صورة QR للطالب بصيغة PNG |
| `POST` | `/api/lectures` | إنشاء محاضرة. البيانات: `title` و`startTime` و`endTime` بصيغة ISO مثل `2026-10-05T09:00:00Z` |
| `GET` | `/api/lectures` | عرض المحاضرات |
| `POST` | `/api/attendance` | تسجيل حضور. البيانات: `qrCodeToken` و`lectureId` |
| `GET` | `/api/lectures/:id/attendance` | عرض الطلاب الحاضرين في محاضرة |

## شروط تسجيل الحضور

لما يتم مسح الـ QR، الـ service بتتحقق من الشروط بهذا الترتيب:

1. التأكد إن الـ token يعود لطالب مسجّل (إذا لا يرجع 404).
2. التأكد إن المحاضرة موجودة (إذا لا يرجع 404).
3. التأكد إن الوقت الحالي بين بداية المحاضرة ونهايتها (إذا لا يرجع 400).
4. التأكد إن الطالب ما سجّل حضوره لنفس المحاضرة قبل (إذا سجّل يرجع 409).

الشرط الرابع اعتمدت فيه على القيد الفريد `@@unique` في قاعدة البيانات بدل ما أفحص يدوياً قبل الإضافة، لأنه لو وصل طلبين بنفس اللحظة الفحص اليدوي ممكن يمرّرهم الاثنين.

## ما تعلمته

- الفرق بين بناء مشروع بـ Express وربط الأجزاء يدوياً، وبين NestJS اللي بيربطها تلقائياً.
- فصل الكود إلى routes و controllers و services.
- استخدام قيود قاعدة البيانات لمنع التكرار.
- معالجة الأخطاء في مكان واحد بدل تكرارها في كل controller.
